# 水豚噜噜桌面宠物设计方案

版本：v1.0

## 1. 产品定位

项目不做“宠物图鉴”，只做一只长期陪伴用户的水豚宠物：**噜噜**。

噜噜的核心价值不是展示很多宠物，而是用丰富、短促、低打扰的动画，让任务管理变得有情绪反馈：用户添加任务时它回应，完成任务时它庆祝，到点时它提醒，长时间没有操作时它自然地生活。

设计关键词：

- 单一角色，强化记忆点
- 慢节奏、治愈、略带幽默
- 动画丰富，但不妨碍工作
- 操作路径短，宠物本身就是入口
- 素材可持续扩展，不依赖每次改业务代码

## 2. 角色设定：水豚噜噜

### 2.1 视觉方向

建议采用“圆润卡通 + 轻微手绘质感”的风格，而不是写实水豚或复杂二次元立绘。

- 主色：暖棕色、奶油色、浅橙色
- 轮廓：大头、短腿、低重心、清晰剪影
- 表情：眼睛和嘴巴面积较小，避免缩小后糊成一团
- 配件：最多保留 1 个固定识别物，例如绿色小围巾或叶子发夹
- 透明背景，所有动作保持相同画布尺寸和脚底基线
- 重点突出脸部、耳朵、前脚和身体重心变化

### 2.2 性格

噜噜不是高频吵闹型助手，而是“安静但会回应”的桌面伙伴。

- 平时：慢慢呼吸、眨眼、发呆
- 被点击：抬头、歪头、挥手
- 被拖动：四肢乱晃，落地后整理姿势
- 任务完成：先愣一下，再开心蹦跳
- 到点提醒：认真举牌或敲小铃铛
- 久坐提醒：递水、伸懒腰、趴下休息

## 3. 动画系统设计

### 3.1 不把动画写死在组件里

当前 `PetSprite` 通过 `skin` 和 `state` 直接选择 SVG。建议改为“动画目录 + 播放器 + 状态机”三层：

```text
PetStateMachine  ->  AnimationController  ->  AssetRenderer
     决策状态             播放队列              SVG/Lottie/WebP
```

业务代码只发送事件，不关心素材格式：

```ts
pet.play('task-complete')
pet.play('reminder', { priority: 'high' })
pet.setMood('calm')
```

### 3.2 动画分类

建议第一批制作 24 个动作，后续扩展到 40—60 个。每个动作尽量控制在 0.5—3 秒，循环动作单独标记。

| 类别 | 动画建议 | 用途 |
|---|---|---|
| 日常循环 | idle、breathing、blink、look-around、yawn、sleep | 无事件时随机播放 |
| 交互反馈 | tap、double-tap、head-tilt、wave、drag、land | 用户操作反馈 |
| 任务操作 | task-add、thinking、task-complete、task-delete、undo | 任务 CRUD |
| 时间提醒 | reminder、urgent-reminder、snooze、late | 到点和逾期 |
| 情绪 | happy、proud、confused、sad、shy、angry-cute | AI 或系统情绪 |
| 工作陪伴 | focus-start、focus-rest、stretch、drink-water | 番茄钟/久坐提醒 |
| 彩蛋 | eat-watermelon、hot-spring、rainy-day、dance、faint | 低概率随机事件 |

### 3.3 播放规则

动画必须有优先级和打断策略，否则“动画越多”会变成视觉噪音。

```ts
type AnimationPriority = 'ambient' | 'interaction' | 'system' | 'urgent'

interface PetAnimation {
  id: string
  file: string
  loop?: boolean
  priority: AnimationPriority
  interruptible: boolean
  cooldownMs?: number
}
```

推荐规则：

1. `urgent` 可以打断所有非紧急动画。
2. `system` 可以打断日常循环，但不能连续刷屏。
3. `interaction` 立即响应用户，但播放结束后回到 idle。
4. `ambient` 只能在空闲时播放，并设置随机间隔和冷却时间。
5. 同一动画连续触发时合并事件，例如短时间内完成多个任务只庆祝一次或升级成连击动画。

## 4. 素材技术方案

### 4.1 推荐组合

不要让 AI 直接生成最终可用的整套动画视频。更稳定的方案是：

- 角色原画：AI 生成参考图，再人工确定标准立绘
- 简单循环：SVG/CSS 或 Lottie
- 复杂动作：AI 生成关键帧/动作参考，人工拆分后制作 Lottie
- 彩蛋和短片：透明 WebM/WebP/GIF，按需加载

这样既能保持角色一致，也能控制安装包大小和播放性能。

### 4.2 素材目录

建议将当前 `src/renderer/public/assets/pets/` 改为：

```text
src/renderer/public/assets/pets/capybara/
├── manifest.json
├── base/
│   ├── capybara.svg
│   └── capybara-shadow.svg
├── lottie/
│   ├── idle-breathe.json
│   ├── blink.json
│   ├── task-complete.json
│   └── reminder.json
├── webp/
│   └── dance.webp
└── thumbnails/
```

`manifest.json` 统一描述动画，播放器通过 ID 查找素材，而不是在 React 组件中写路径。

## 5. AI 生成工作流

### 5.1 先建立角色锁定包

在生成动画前，先制作一套固定参考资料：

- 正面、侧面、背面三视图
- 6—8 个基础表情
- 固定色板和线条粗细
- 固定画布尺寸、脚底基线和阴影
- 正向提示词、反向提示词、种子值或参考图

每次生成都必须带同一张角色参考图和同一套角色描述。不要只依赖“请生成一只可爱的水豚”，否则服装、脸型、颜色和比例会漂移。

### 5.2 推荐提示词模板

```text
同一个原创卡通水豚角色“噜噜”，圆润低重心身体，暖棕色毛发，奶油色脸颊，绿色小围巾，短腿，小耳朵，简洁粗线条，治愈系桌面宠物风格。
透明背景，正面三分之二视角，完整身体，脚底保持在同一水平线，画布留出动作空间。
动作：{动作描述}。
保持角色脸型、身体比例、配色、围巾和画风完全一致，不增加其他角色，不添加文字，不添加复杂背景。
```

反向提示词：

```text
写实照片，3D渲染，复杂背景，多角色，额外肢体，手指，文字，水印，改变服装，改变颜色，改变脸型，裁切身体，脚底漂浮，过度细节
```

### 5.3 动画生成步骤

1. AI 生成动作概念图，先验证姿势和情绪。
2. 从概念图中挑选关键帧，统一角色比例。
3. 手工清理边缘、眼睛、围巾和脚底基线。
4. 将身体拆成头、身体、前脚、后脚、耳朵、尾巴、配件等图层。
5. 在 After Effects、Rive、Lottie 或代码中制作可循环动画。
6. 导出前检查透明通道、画布尺寸、帧率、文件大小和循环首尾衔接。
7. 放入 `manifest.json`，通过动画 ID 接入程序。

AI 最适合做“动作创意、关键姿势、表情变化和素材草图”；角色一致性、可循环性、透明边缘和可维护性仍应由人工或程序控制。

## 6. 与任务功能的绑定

| 事件 | 默认动画 | 反馈文案 |
|---|---|---|
| 应用启动 | welcome | “噜噜上线啦” |
| 打开任务面板 | wave | “今天也要稳稳完成” |
| 新建任务 | thinking → task-add | “收到，记下了” |
| 完成任务 | task-complete | “漂亮！又完成一件” |
| 删除任务 | sweep | “清理完成” |
| 到点提醒 | reminder | “该做「任务名」啦” |
| 延后提醒 | sleepy | “好，那一会儿再叫你” |
| 逾期 | worried | “它好像等你有一会儿了” |
| 连续完成 3 项 | combo-dance | “今天状态很好！” |
| 长时间无操作 | stretch / yawn | 不强制弹窗，只做轻提示 |

所有动画触发都应经过统一事件总线，例如 `pet:event`，避免任务服务、通知服务和页面组件各自控制宠物，造成状态冲突。

## 7. 交互与视觉建议

- 默认宠物尺寸建议 120—160px，支持设置中调整大小。
- 任务面板从宠物旁边展开，不要覆盖宠物本体。
- 常驻状态保持低对比度，提醒状态才提高饱和度和动作幅度。
- 气泡文案尽量短，一次只说一件事。
- 允许关闭高频彩蛋、声音和提醒动画；工作场景默认克制。
- 拖拽结束后增加“落地”反馈，增强实体感。
- 任务完成动画应小于 2 秒，避免用户等待。

## 8. 迭代计划

### M1：角色统一

- 移除 cat/dog/robot 选择逻辑
- 新增 `capybara` 类型和默认设置
- 完成标准立绘、idle、tap、task-complete、reminder

### M2：动画播放器

- 引入 `manifest.json`
- 实现动画优先级、队列、冷却和回 idle
- 统一任务、通知、拖拽事件到宠物事件总线

### M3：丰富动画

- 补齐 24 个基础动作
- 增加随机日常行为和组合动画
- 加入动画预览/调试面板

### M4：AI 扩展机制

- AI 根据任务上下文选择情绪和文案
- AI 只返回受控的动画 ID，不允许直接决定任意文件路径或执行代码
- 增加“节日/主题动画包”机制

## 9. 关键验收标准

- 任意动画都可以通过一个动画 ID 播放。
- 新增一个动画不需要修改任务业务逻辑。
- 角色在所有动画中脸型、配色、配件和脚底位置一致。
- 普通 idle 动画不造成明显 CPU 占用或窗口闪烁。
- 提醒动画能够打断 idle，但不会被随机动画覆盖。
- 关闭应用后，任务数据、宠物位置和动画设置均能保留。

## 10. 最终建议

项目应把“水豚噜噜”当作一个品牌角色，而不是一个可替换的皮肤。第一阶段优先把角色一致性、动画调用方式和任务反馈闭环做好；动画数量可以逐步增加，但必须全部挂在统一的动画注册表和事件系统上。AI 用来提高动作创意和生产效率，最终交付则采用可控、轻量、可维护的 SVG/Lottie/WebP 资源。
